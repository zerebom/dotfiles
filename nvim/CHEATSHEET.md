# Neovim コードリーディング チートシート

Next.js (TS/TSX) などのコードを読んで理解するための操作集。
LazyVim ベース + 追加プラグイン(overlook.nvim) を前提にしている。
ファイル検索などの picker は LazyVim 標準の Snacks.picker を使う(Telescope ではない)。
`<leader>` = スペースキー。

---

## ショートカットの覚え方（これが一番大事）

キーを1個ずつ暗記しない。**「最初の1文字でジャンルが決まる」という文法**を覚えると、あとは推測が効く。

### ルール1: 先頭の記号でジャンルが決まる

| 先頭 | 意味 | 例 |
|---|---|---|
| `g` | **g**oto = どこかへ行く | `gd`定義 / `gr`参照 / `gy`型定義 |
| `<Space>` | メニュー（机の引き出し。開くと中身が出る） | `<Space>f…`ファイル系 / `<Space>s…`検索系 |
| `]` / `[` | 次 / 前（同じ種類の次の場所へ） | `]d`次のエラー / `[d`前のエラー |
| `<C-o>` / `<C-i>` | 時間を戻る / 進む（来た道を引き返す） | 潜ったあと元の場所へ |
| `K` | 上に小窓で説明を出す（hover） | 型・docを見る |

### ルール2: `<Space>` の次の1文字 = カテゴリ

`<Space>` を押した後の文字がジャンルの頭文字。**英単語の頭文字なので推測できる**。

| `<Space>` + | カテゴリ | 由来 |
|---|---|---|
| `f` | ファイル系 | **f**ile |
| `s` | 検索系 | **s**earch |
| `c` | コード操作（リネーム・修正・整形） | **c**ode |
| `g` | git系 | **g**it |
| `x` | エラー/診断一覧 | trouble(バツ印) |
| `p` | 覗き見（overlook） | **p**eek |
| `e` | ファイルツリー | **e**xplorer |

### ルール3: 迷ったら which-key に教えてもらう（暗記不要の正体）

**`<Space>` を押して1秒待つ** と、画面下に「次に押せるキーの一覧」がメニューで出る。
これが which-key。つまり**覚えてなくても画面が教えてくれる**。

```
<Space> を押す → メニューが出る → f を押す → さらにファイル系のメニューが出る → ff
```

最初は全部これでいい。`<Space>` → 待つ → 出たメニューを見て選ぶ。
使ううちに「ファイルは ff」と手が勝手に覚える。**暗記ではなく反復で身につく**設計になってる。

### まとめ: 覚えるのはこの3つだけ

1. `g` = 行く、`<Space>` = メニュー、`]`/`[` = 次/前、`<C-o>` = 戻る
2. `<Space>` の次は英単語の頭文字（f=file, s=search, c=code…）
3. 分からなければ `<Space>` を押して1秒待つ → メニューが出る

## 0. 前提セットアップ（最初に一度だけ）

TS/TSX のジャンプ・型表示を効かせるには LazyVim の TypeScript extra が必須。

```vim
:LazyExtras
```
で開き、以下を `x` で有効化する:

- `lang.typescript`  — vtsls(LSP) + tsx parser。**これが無いと gd/peek が効かない**
- `lang.tailwind`    — Tailwind クラス補完（任意）
- `lang.eslint`      — ESLint 連携（任意）
- `lang.json`        — JSON補完（任意）

有効化後、`.tsx` を開いて `:LspInfo` で `vtsls` が attached になっているか確認する。

追加プラグイン overlook.nvim は `lua/plugins/overlook.lua` で導入済み。
`:Lazy sync` で取得される。

## 1. ジャンプ系（LazyVim デフォルト・最頻出）

| キー | 動作 |
|---|---|
| `gd` | 定義へジャンプ（コンポーネント・関数の実体へ移動） |
| `gr` | 参照一覧（このシンボルがどこで使われているか） |
| `gI` | 実装へジャンプ |
| `gy` | 型定義へジャンプ |
| `gD` | 宣言へジャンプ |
| `K` | ホバー（型・シグネチャ・docをその場表示）。もう一度押すとホバー窓内に入れる |
| `<C-o>` | ジャンプ履歴を**戻る**（潜ったあと元の場所へ） |
| `<C-i>` | ジャンプ履歴を**進む** |

> 基本ムーブ: `gd` で潜る → 読む → `<C-o>` で戻る、の往復。

## 2. peek / overlook（フロート窓プレビュー・追加プラグイン）

`gd` は「移動」なので元の場所を離れる。**離れずにチラ見したいとき**は overlook を使う。
ポップアップは積み重なり(スタック)、`q` で1枚ずつ閉じて元に戻れる。

| キー | 動作 |
|---|---|
| `<leader>pd` | カーソル下の定義をフロート窓でプレビュー（一番使う） |
| `<leader>pp` | 現在のカーソル位置をポップアップ化（固定メモ的に残す） |
| `<leader>pf` | ポップアップ ⇄ 元ウィンドウのフォーカス切替 |
| `<leader>pu` | 直前に閉じたポップアップを復元 |
| `<leader>pc` | 全ポップアップを閉じる |
| `<leader>ps` | ポップアップを水平分割の実ウィンドウに昇格 |
| `<leader>pv` | ポップアップを垂直分割に昇格 |
| `<leader>pt` | ポップアップを新規タブに昇格 |
| `<leader>po` | 現在ウィンドウをポップアップ内容で置換 |
| `q`（窓内） | ポップアップを閉じる |

> ポップアップ内は普通のバッファ。中でさらに `<leader>pd` すると次の定義が上に積まれる。
> 「コンポーネント → その子 → さらに型」と潜っても、閉じれば元の行に戻る。

## コードリーディング実践フロー

コードを読むのは1本道ではなく、次の4ステップをぐるぐる回す。
**広く掴む → 入口を見つける → 潜る → 戻る**。道具はステップごとに変わる。

### 頭の中のフローチャート

```
読みたいものの「名前」を知ってる?
├─ YES → <Space>ff で開く
└─ NO  → <Space>sg で文字列grep / <Space>e で構造から探す
            ↓
        入口のファイルを開いた
            ↓
        gd で定義へ潜る ⇄ <C-o> で戻る  ← メインループ
        ちょい見だけ      → <leader>pd（フロート）→ q で閉じる
        誰が使ってる?      → gr（逆引き）
        型を確認           → K
        ファイル内の目次   → <leader>ss
```

### シナリオA: 初めてのリポジトリ（全体像ゼロ）

まだコードは読まない。地図を見るだけ。

1. `<Space>gr` → リポジトリへ移動
2. `<Space>e` → explorer で `app/ components/ lib/` の配置を頭に入れる
3. `<Space>ff README` → README / package.json で何のアプリか把握

### シナリオB: 「この画面どう動いてる？」（最頻出）

1. `<Space>ff page` → `app/page.tsx` を開く
2. JSX内の `<UserList />` 上で `gd` → 実体へジャンプ
3. `K` → props や型をホバー確認
4. 中の `useUsers()` 上で `<leader>pd` → フロートでチラ見（元を離れない）
5. `q` でフロートを閉じる
6. `<C-o>` で `gd` の分を1段戻る

> gd（移動して読む）と pd（離れずチラ見）の使い分けが肝。
> じっくり辿る→`gd`+`<C-o>`、型や短い関数の確認だけ→`<leader>pd`+`q`。

### シナリオC: 「これどこで使われてる？」（逆引き・影響範囲調査）

1. 関数/コンポーネント名の上で `gr` → 参照一覧（Trouble）
2. `j`/`k` で選んで `Enter` → 使用箇所へ
3. `<C-o>` で戻り、別の箇所も見る

### シナリオD: 「あの文言/UI どこで作ってる？」（名前すら知らない）

1. `<Space>sg` → 全文 grep
2. 画面に出てる文言（例 "ログインに失敗"）や className を打つ
3. `Enter` で開く → `gd` で関連実装へ潜る

### シナリオE: 長いファイルの構造を掴む

1. `<leader>ss`（目次）or `<leader>cs`（サイドにアウトライン常駐）
2. 目的の関数を選んでジャンプ

### 迷子になったときの復帰

| 状況 | キー |
|---|---|
| どこまで潜ったか分からない | `<C-o>` 連打で戻る |
| フロート窓が散らかった | `<leader>pc`（全部閉じる） |
| 今どのファイル？ | 画面隅の incline 表示を見る |
