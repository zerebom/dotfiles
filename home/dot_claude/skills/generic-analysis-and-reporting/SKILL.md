# 汎用データ分析＆レポーティング

任意のドメインの表形式データを分析し、ビジネス示唆を含むレポートを生成するスキル。

## ワークフロー概要

```
Step 1: 目的・コンテキスト確認
    ↓
Step 2: データ理解と前処理方針
    ↓
Step 3: 分析方針（プラン）作成
    ↓ ユーザー承認
Step 4: 分析実行（ループ）
    ↓
Step 5: インサイト・示唆の整理
    ↓
Step 6: レポート生成
```

## Step 1: 目的・コンテキスト確認

分析開始前に、以下を必ずユーザーに確認し「分析ブリーフ」としてまとめる。

### 確認項目チェックリスト

- [ ] ビジネス／プロダクトの背景（何のサービス・事業か）
- [ ] 解きたい問い（1〜3個）
- [ ] 想定読者・意思決定者（誰のためのレポートか）
- [ ] 時間軸（過去分析／現状把握／将来予測のどれが主か）
- [ ] 制約（データ範囲、分析時間、技術的制約など）

### 分析ブリーフのフォーマット

```markdown
## 分析ブリーフ

- **背景**: [サービス・事業の概要]
- **解きたい問い**:
  1. [問い1]
  2. [問い2]
  3. [問い3]
- **想定読者**: [経営層/PdM/エンジニア など]
- **時間軸**: [過去/現在/将来]
- **制約**: [データ範囲、時間制約など]
```

ブリーフ作成後、ユーザーに確認を取ってから次へ進む。

## 実行環境とデータ取得の方針

### データソースの優先順位

1. ユーザーがチャットに添付したファイル、もしくは会話の中で明示的に指定されたパス
2. プロジェクト内の `data/` ディレクトリなど、ユーザーが「分析用データを置く場所」として合意したディレクトリ
3. 追加でユーザーが指定する補助的なファイル・ディレクトリ

- データの所在が不明な場合は、必ずユーザーに次を確認する：
  - 「どのファイル（パス）を主な分析対象にすればよいか」
  - 「他に補助的に参照すべきファイルはあるか」

### 実行環境の前提

- Claude Code など、コード実行が可能な環境を想定する。
- 可能な限り Python + pandas を用いた集計・可視化を行う。
- 追加ライブラリが必要な場合は、グローバル環境ではなくプロジェクトローカル環境（例: 仮想環境や `uv` 等）にインストールすることを推奨する。
- 行数が非常に多いデータ（数十万行〜）の場合は、サンプリングや事前集約を検討する。

## Step 2: データ理解と前処理方針

### データ確認チェックリスト

- [ ] カラム一覧と各カラムの意味を把握
- [ ] データ型の確認（カテゴリ/数値/日付/ID等）
- [ ] 単位・スケールの確認（円/ドル、%、件数など）
- [ ] 欠損値の有無と割合
- [ ] 外れ値・異常値の有無
- [ ] エンコード問題（`+`, `%`, 通貨記号など）の確認

### 前処理方針メモのフォーマット

```markdown
## 前処理方針

| 項目 | 現状 | 対応方針 |
|------|------|----------|
| 欠損値 | [カラム名: X%] | [除外/補完/そのまま] |
| 外れ値 | [カラム名: 範囲外X件] | [除外/クリップ/そのまま] |
| 型変換 | [カラム名] | [文字列→日付 など] |
```

### Pythonでのデータ確認例

```python
import pandas as pd

df = pd.read_csv("data.csv")

# 基本情報
print(df.shape)
print(df.dtypes)
print(df.describe())

# 欠損値
print(df.isnull().sum())

# カテゴリカラムのユニーク値
for col in df.select_dtypes(include=['object']).columns:
    print(f"{col}: {df[col].nunique()} unique values")
```

## Step 3: 分析方針（プラン）作成

### プラン作成チェックリスト

- [ ] 各問いに対して使用指標・観点を定義
- [ ] 使用手法を決定（集計/グラフ/相関/検定など）
- [ ] 期待アウトカムを明文化
- [ ] ユーザーにプランを提示し承認を得る

### 分析プランのフォーマット

```markdown
## 分析プラン

### 問い1: [問いの内容]

| 観点 | 手法 | 期待アウトカム |
|------|------|----------------|
| 推移 | 折れ線グラフ | トレンドの把握 |
| 分布 | ヒストグラム | 中央値・外れ値の確認 |
| セグメント比較 | グループ別集計 | 差異の特定 |

### 問い2: [問いの内容]
...
```

**重要**: プランをユーザーに提示し、「この方針で進めてよいか」を確認する。

## Step 4: 分析実行（ループ）

各問いに対して以下のループを実行する。

### 分析実行チェックリスト（問いごと）

- [ ] 必要な集計・可視化を実施
- [ ] 結果を「事実」と「解釈」に分けて記録
- [ ] 追加で見たい切り口があれば提案

### 可視化の基本パターン

可視化を行う際は、以下の方針とする：

- 画像ファイルは、現在の作業ディレクトリ配下の `analysis_outputs/plots/` ディレクトリに保存する（存在しない場合は作成してから保存する）。
- 各プロットについて、ファイルパスだけでなく「何を見て何が言えるのか」を Markdown で文章として記述する。
- 画像を見なくても、テキストだけでおおよその傾向が伝わるように説明を書く。

```python
import matplotlib.pyplot as plt
import seaborn as sns

# 日本語フォント設定
plt.rcParams['font.family'] = 'Hiragino Sans'

# 推移: 折れ線グラフ
plt.figure(figsize=(10, 6))
plt.plot(df['date'], df['value'])
plt.title('指標の推移')
plt.xlabel('日付')
plt.ylabel('値')
plt.xticks(rotation=45)
plt.tight_layout()
plt.savefig('trend.png', dpi=150)

# 分布: ヒストグラム
plt.figure(figsize=(8, 6))
sns.histplot(df['value'], bins=30)
plt.title('値の分布')
plt.savefig('distribution.png', dpi=150)

# 比較: 棒グラフ
plt.figure(figsize=(10, 6))
sns.barplot(data=df, x='category', y='value')
plt.title('カテゴリ別比較')
plt.xticks(rotation=45)
plt.tight_layout()
plt.savefig('comparison.png', dpi=150)

# 相関: ヒートマップ
plt.figure(figsize=(10, 8))
sns.heatmap(df.corr(), annot=True, cmap='coolwarm', center=0)
plt.title('相関行列')
plt.tight_layout()
plt.savefig('correlation.png', dpi=150)
```

### 分析結果の記録フォーマット

```markdown
### 問い1の分析結果

**事実（ファクト）**:
- [データから読み取れる客観的事実1]
- [データから読み取れる客観的事実2]

**解釈**:
- [事実に基づく解釈・考察]

**追加分析の提案**:
- [さらに深掘りしたい観点があれば]
```

### 統計手法（必要に応じて使用）

- 相関分析: `df.corr()`
- t検定: `scipy.stats.ttest_ind()`
- ANOVA: `scipy.stats.f_oneway()`
- カイ二乗検定: `scipy.stats.chi2_contingency()`

**注**: 統計手法はデータとドメインに応じて適切なものを選択。必須ではない。

## Step 5: インサイト・示唆の整理

単なる事実の羅列ではなく、以下の観点で整理する。

### インサイト整理チェックリスト

- [ ] What: 何が起きているか
- [ ] Why: なぜそれが重要か
- [ ] Who: 誰にとって重要か
- [ ] So what: どのようなアクションにつながるか

### インサイトの記述構造

各インサイトは「ファインディング → エビデンス → 解釈」の三段構造で記述する。

```markdown
#### インサイト1: [タイトル]

**ファインディング**: [発見した事象を1文で]

**エビデンス**:
- [裏付けるデータ・数値1]
- [裏付けるデータ・数値2]

**解釈・示唆**:
- [ビジネス観点での意味]
- [推奨されるアクション]
```

## Step 6: レポート生成

[TEMPLATES.md](TEMPLATES.md) のレポートテンプレートに従って最終レポートを生成する。

### レポート生成チェックリスト

- [ ] 背景と目的を記載
- [ ] データ概要を記載
- [ ] 主要な発見（Key Findings）を3〜5個に絞る
- [ ] インパクトと示唆を記載
- [ ] アクション案を優先度付きで記載
- [ ] 制約と今後の分析を記載

### レポート出力と保存場所

- デフォルトの保存先:
  - 現在の作業ディレクトリ配下の `analysis_outputs/reports/` ディレクトリ（存在しない場合は作成してから保存する）。
- ファイル名の推奨ルール:
  - `YYYYMMDD_topic.md` 形式（例: `20251206_signup_funnel_analysis.md`）
- ユーザーが保存先や命名規則を指定した場合は、それを優先する。
- レポート内には、使用したデータファイルのパスと、生成した可視化画像ファイルのパスを明記する。

## 注意事項

- 本スキルはドメイン非依存。ドメイン固有の前提はユーザーから教えてもらうか、データから推測する
- 可視化にはmatplotlib、seabornを使用。日本語フォント設定を忘れずに
- 中小規模データ（数千〜数万行）を想定。大規模データの場合はサンプリングを検討
- レポートは日本語で出力
