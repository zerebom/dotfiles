# AI セッションの振り返り

## 手順

### 1. 材料を出す

```bash
uv run python ~/.claude/skills/ai-session-review/scripts/extract.py 2026-11-09
uv run python ~/.claude/skills/ai-session-review/scripts/extract.py 2026-11-03 2026-11-09
```

- 日付を省くと今日（JST）になる。日付は `/bin/date +%Y-%m-%d` で取る
- 今の会話は自動で除く。ほかに除きたいセッションがあれば `--exclude <ID の先頭>` を足す
- 出力は次の 5 つ
  1. セッションの一覧（開始、ID、作業フォルダ、本人の発言数、最初の発言、最後の AI 応答）
  2. 1 時間ごとの発言数と、触っていたセッション
  3. セッションの切り替えの回数と、発言の並び
  4. 承認だけの発言（「いいよ」「ok」「1」など）の数
  5. 詰まりの合図（「なんで」「訳わか」「びっくり」などを含む発言）
- 作業者のセッション（最初の発言が「目的:」「指示書:」）は一覧に（作業者）と付く。指示書とオーケストレーターからの指示は数えず、本人が作業者に直接打った発言だけを数える

ログの置き場所と、スクリプトが外している行は「ログの事実」を見る。

### 2. セッションにテーマ名を付ける

一覧の最初の発言と最後の AI 応答から、セッションごとに短いテーマ名（「Renovate の自動マージ」「Kaggle」など）を付ける。

- 同じ仕事が複数のセッションに分かれていたら、同じテーマ名にまとめる（compact の後や、作業者に回した分など）
- 名前を付けたら、表 2 と表 3 をテーマ名で読み直す。切り替えの回数は、発言の並びで「前と違うテーマに移った回数」を数え直す
- 判断がつかないセッションは、ログのファイルを開いて最初の数発言を読む

### 3. Y（やったこと）の材料をまとめる

テーマごとに、何をして、どこまで進んだかを 1〜2 行で書く。カロリーが高い順に並べる。

- カロリーは、本人の発言数と、詰まりの合図の多さと、判断の重さ（設計を決めた、レビューで差し戻した）で見る。発言数だけで決めない
- 終わったことと、止まったまま次に持ち越すことを分けて書く。最後の AI 応答が質問で終わっているセッションは、持ち越しの候補になる

### 4. AI の使い方で気づいたことを出す

3 つ前後に絞る。数を並べるのではなく、そこから言えることを書く。見る観点は次のとおり。

- 集中と切り替え: 1 時間に触ったテーマの数、同じテーマに続けていた時間、切り替えが多かった時間帯
- 詰まった場面: 詰まりの合図の前後で、AI が何を返していたか。前の発言とセットで読む
- 承認だけの割り込み: 承認だけの発言が多いセッションは、AI が確認を求めすぎているか、任せる範囲が狭い

直す提案は、スキルや CLAUDE.md の変更に結びつくものを先に出す（例: 「この確認は聞かずに進めてよい」と CLAUDE.md に書く）。

### 気づいたことを出すときの注意

過去の振り返りで実際に外したことに基づく。

- **原因を言う前に、発言の時刻の並びを確かめる。** 「理解より先に実装を頼んだ」と言ったが、実際は MTG で懸念が解けてから頼んでいた。前後の発言と、ほかのセッションの同じ時間帯を読んでから原因を書く
- **割り込みに見えても、本人の狙いのことがある。** マシンを遊ばせないために Kaggle をこまめに動かしていた日があった。決めつけず、「〜の狙いがあったか」を聞ける形で書く
- **切り替えの回数は、頭の切り替えの重さそのものではない。** 数えた発言には「ok」のような短い返事も入る。回数を出すときは、このことを一言添える

## /reflect から呼ばれたとき

Y の材料（手順 3）と、気づいたこと（手順 4）だけを返す。ジャーナルへの書き込みは /reflect 側が行うので、このスキルではファイルを書かない。

## ログの事実

- ログは `~/.claude/projects/<作業フォルダの / を - に替えた名前>/<セッション ID>.jsonl`。サブエージェントのログは `<セッション ID>/subagents/` の下にあり、対象にしない
- ファイルの更新時刻では日付を絞れない。11/9 に更新されたファイルでも、中身は 11/2〜11/6 のものがあった。スクリプトは各行の `timestamp`（UTC）を JST に直して日付で絞る
- 再開や分岐で作られたファイルには、元のセッションの行が元の `sessionId` のまま写っている。スクリプトはファイル名と `sessionId` が違う行を捨てて、二重に数えないようにしている
- 本人の発言から外している行: `isMeta`、`<task-notification`、`<hc from=`（オーケストレーターから作業者への指示）、`<local-command`、`<system-reminder>` などのハーネスが差し込んだタグ、compact の要約（`This session is being continued`）、`[Request interrupted`、別セッションからのメッセージ、`/clear` や `/compact` などの画面操作のコマンド。最初の発言が `<scheduled-task` のセッション（定期実行）は丸ごと外す
- フォルダ名が `-` で始まるため、シェルで `ls */<ID>*.jsonl` と渡すと ls がオプションと読んで失敗する。ログを自分で開くときは Python の glob を使うか、`--` を付ける
