# スイムレーン図作成

BPM手法に基づいた構造化インタビューを通じて、draw.io形式の業務プロセススイムレーン図を作成します。

## ワークフロー

BPM方法論に基づく5ステップのアプローチに従います。

### ステップ1: 意図の明確化

ユーザーに以下を確認します。
- **タイプ**: As-Is（現状）またはTo-Be（将来像）？
- **対象プロセス**: どの業務プロセスを可視化するか？（例: 「顧客問い合わせ対応」「受注処理」「採用プロセス」）
- **スコープ**: プロセスの開始と終了はどこか？
- **主要指標**（任意）: どの指標が重要か？（リードタイム、コスト、エラー率、顧客満足度）

### ステップ2: プロセス情報の収集

プロセスの詳細を収集するための構造化インタビューを実施します。詳細なインタビュー技法については `references/bpm_guideline.md` を参照してください。

以下の必須要素について質問します。
- **アクター（スイムレーン）**: 誰が関与するか？（部門、役割、システム）
- **トリガー（イベント）**: プロセスを開始するものは何か？
- **アクティビティ（タスク）**: どのようなアクションが実行されるか？どのような順序か？
- **決定ポイント（ゲートウェイ）**: どのような判断が行われるか？分岐は何か？
- **成果物（オブジェクト）**: どのような文書、データ、ツールが使用されるか？
- **引き継ぎ**: アクター間で責任がどこで移転するか？

図を生成する前に、プロセス構造の理解をユーザーに提示して確認を取ります。

### ステップ2.5: 座標計画とレイアウト設計

**新ステップ**: Draw.io XMLを生成する前に、エンティティの位置を事前に計画します。

`references/coordinate_planning_template.md` のテンプレートに従って、座標計画を実施します。

**目的**:
- エンティティの座標を事前に設定し、重複を防ぐ
- 適切なスペーシングを確保する
- ユーザーに視覚的なレイアウトを提示し、承認を得る

**手順**:

1. **キャンバスサイズの計算**:
   - 幅 = 120 (左マージン) + (ステップ数 × 200) + 120 (右マージン)
   - 高さ = 120 (上マージン) + (アクター数 × 160) + 40 (下マージン)

2. **スイムレーンレイアウトの定義**（Y軸）:
   - 各アクターに160pxの高さを割り当て
   - 最初のレーンのY開始 = 120（上マージン）
   - 次のレーンのY開始 = 前のレーンのY終了

3. **エンティティ位置の計算**（X軸: 時間進行）:
   - 最初のエンティティ: X = 160
   - 次のエンティティ: X = 前のX + 前の幅 + 最小ギャップ（120px）
   - テキスト幅: 日本語1文字あたり30-40px

4. **スペーシング検証**:
   - 水平ギャップ: 最小120px
   - 垂直マージン: 最小40px（レーン境界から）
   - 矢印ラベルクリアランス: 最小40px
   - 重複チェック: すべてのエンティティが重複していないこと

5. **視覚的ASCIIマップの生成**:
   ```
   ┌────────────────────────────────────┐
   │ Actor1                             │
   │   [開始]──→[タスク1]──→[判断]    │
   │                           ↓        │
   ├─────────────────────────┼─────────┤
   │ Actor2                  ↓          │
   │                      [タスク2]     │
   └────────────────────────────────────┘
   ```

6. **ユーザー確認**:
   ```
   このレイアウトで進めますか？ (yes/no/modify)
   ```

### ステップ3: 出力先の確認

**新ステップ**: ファイルを作成する前に、出力先とファイル名を確認します。

**デフォルト命名規則**:
- `YYYY-MM-DD-{process-name-kebab-case}.drawio`
- 日付は `/bin/date +%Y-%m-%d` で取得
- プロセス名をkebab-caseに変換

**デフォルトパス提案**:
- 探索的な図: `side/tmp/swimlane_outputs/`
- プロダクション図: `work/products/{product}/docs/`

**確認プロンプト**:
```
=== 出力先の確認 ===

推奨ディレクトリ: {default_directory}
推奨ファイル名: {YYYY-MM-DD-process-name}.drawio

以下のファイルが生成されます:
- {process-name}.drawio (ソースファイル)
- {process-name}.png (PNG出力)

この出力先でよろしいですか？
[デフォルトを使用 / カスタムパスを指定]
```

### ステップ4: Draw.ioファイルの生成

`references/create_drawio_guideline.md` のベストプラクティスに従って `.drawio` ファイルを生成します。

**重要ルール**（draw.ioの一般的な落とし穴を防ぐために）:

0. **レイアウト方向**（最重要）:
   - X軸: 時間の進行（左から右へ）
   - Y軸: アクター/部門/役割（水平スイムレーン）
   - 各スイムレーンは1つのアクター（人、部門、またはシステム）を表す
   - アクティビティはレーン内で水平に流れ、時系列を示す

1. **XML構造**:
   - スイムレーン内のすべての要素には `parent="laneX"` 属性が必須
   - 矢印には `source="elementId" target="elementId"` を使用（座標ベースは不可）
   - BPMN標準シンボルを使用:
     - 開始/終了: `ellipse` スタイル
     - アクティビティ: `rounded=1` の矩形で `arcSize=10`
     - 決定: `rhombus`

2. **テキストの可視性**（重要）:
   - すべてのテキスト要素に必ず `fontColor=#000000;` を追加
   - 白いボックス（`fillColor=#ffffff`）には黒いテキストが必要
   - すべてのテキスト要素の `style` に `fontFamily=Noto Sans JP;` を設定
   - 可読性のため `fontSize=18`（最小）を使用

3. **矢印の接続**:
   - `edge="1"` と `source="id1" target="id2"` 属性を使用
   - ラベルはテキストコンテンツを持つ独立した `<mxCell>` として追加
   - ラベルは矢印パスから少なくとも40px離す
   - きれいな直角接続のため `edgeStyle=orthogonalEdgeStyle` を使用

4. **テキストサイズ**:
   - 日本語テキスト: 1文字あたり30-40pxの幅を割り当て
   - 望ましくない改行を防ぐため `<mxGeometry>` で十分な `width` を設定
   - 複数行テキスト: 明示的な改行には `&#xa;` を使用

5. **スイムレーンの色**（柔らかく区別できる色を使用）:
   - レーンA: `fillColor=#dae8fc;strokeColor=#6c8ebf;fontColor=#000000`（青）
   - レーンB: `fillColor=#d5e8d4;strokeColor=#82b366;fontColor=#000000`（緑）
   - レーンC: `fillColor=#f8cecc;strokeColor=#b85450;fontColor=#000000`（ピンク）

開始点として `assets/swimlane_template.drawio` のテンプレートを使用してください。

### ステップ5: 自動レビューと反復

**🚨 必須**: このステップでは**必ずレビューサブエージェントを起動**してください。手動でチェックリストを適用してはいけません。

**重要**: すべてのチェックリスト項目が合格するまで、ユーザーに図を提示しないでください。

1. **PNGへの変換** `scripts/convert_to_png.sh` を使用（白背景）:
   ```bash
   bash scripts/convert_to_png.sh <diagram.drawio>
   ```
   これにより `diagram.png` が作成されます（`diagram.drawio.png` ではありません）

2. **レビューサブエージェントの起動**（必須）:

   **🔴 ここで必ずTask toolを使用してレビューサブエージェントを起動すること**

   `agents/swimlane-review.md` で定義されたサブエージェントを起動します：

   ```
   Task tool呼び出し:
   - subagent_type: "swimlane-review"
   - description: "スイムレーン図のレビュー"
   - prompt: |
     以下のパラメータでレビューを実行してください：
     - png_path: "{実際のPNGファイルパス}"
     - drawio_path: "{実際のdrawioファイルパス}"
     - checklist_path: "references/checklist.md"
     - output_report_path: "{diagram-path}-review-iteration-{N}.md"
     - iteration: {現在のイテレーション番号}
     - max_iterations: 3
     - process_name: "{プロセス名}"
   ```

   **出力ファイル命名規則**:
   - イテレーション1: `{diagram-name}-review-iteration-1.md`
   - イテレーション2: `{diagram-name}-review-iteration-2.md`
   - イテレーション3: `{diagram-name}-review-iteration-3.md`

3. **Task完了を待つ**: サブエージェントが完了するまで待機します。

4. **レビューレポートを読み込む**: サブエージェントが生成したレポートファイルを読み込みます。
   ```
   Read tool: {output_report_path}
   ```

5. **レビュー結果の処理**:

   読み込んだレポートファイルの「ステータス」行を確認：

   - **ステータス: PASS**: すべてのチェック項目が合格 → ステップ8（ユーザーへの提示）へ
   - **ステータス: FAIL**: 不合格項目あり → ステップ7（自動修正と再生成）へ

   **レポートファイルの保存場所**: drawioファイルと同じディレクトリ

6. **リトライロジック**（最大3回）:

   - **イテレーション1**: 初回レビュー → FAIL時はレポート(`*-review-iteration-1.md`)の推奨事項に従って修正
   - **イテレーション2**: 再レビュー（iteration=2でサブエージェント再起動） → FAIL時はレポート(`*-review-iteration-2.md`)の推奨事項に従って修正
   - **イテレーション3**: 最終レビュー（iteration=3でサブエージェント再起動） → FAIL時はステップ7へ

   各イテレーションのレビューレポートは履歴として保存されます。

7. **手動フォールバック**（3回失敗時のみ）:

   3回のリトライ後も不合格の場合のみ、以下を実施：
   - 最終レビューレポート(`*-review-iteration-3.md`)をユーザーに提示
   - 手動介入を依頼
   - 過去3回のレビューレポートの参照パスを提示

   **注意**: このフォールバックは例外的な状況でのみ使用。通常はサブエージェントのレビューで完結させること。

6. **検証チェックリスト概要** - レビューサブエージェントが確認する項目:

   **🚨 矢印ルーティング品質（PNG目視必須・最重要）:**
   - [ ] **矢印の交差がない**: PNG上で矢印同士が×印のように交差していない
   - [ ] **矢印の密集がない**: 1ノードに3本以上の矢印が集中していない
   - [ ] **クロスレーン矢印が垂直**: レーンをまたぐ矢印が真下に落ちている（斜め横断していない）
   - [ ] **矢印がノードを通過していない**: 矢印の経路が他ボックスの上を通っていない

   **座標ベース検証（drawio XMLから算出）:**
   - [ ] **水平ギャップ≧120px**: 同一レーン内の隣接エンティティ間
   - [ ] **クロスレーン矢印の垂直整列**: source/targetのX中心差≦50px
   - [ ] **分岐元ノード出力数≦3**: 4本以上ある場合はノード統合が必要

   **基本品質チェック:**
   - [ ] **テキストが読める**: すべてのテキストが明るい背景に黒字（白地に白字ではない）
   - [ ] **矢印が接続している**: すべての矢印がボックスに接続（空中に浮いていない）
   - [ ] **スイムレーンが正しい**: 要素がスイムレーンの境界内にある
   - [ ] **X軸が時間**: プロセスが左から右に流れる
   - [ ] **Y軸がアクター**: 各レーンが1つのアクター/部門を表す
   - [ ] **フォント設定**: `fontFamily=Noto Sans JP; fontSize=18; fontColor=#000000;`
   - [ ] **矢印ラベル**: 矢印ラインと重なっていない（40px以上の間隔）
   - [ ] **日本語テキスト**: 予期しない改行がない
   - [ ] **BPMNシンボル**: 開始/終了が楕円、アクティビティが角丸矩形

7. **自動修正と再生成** - レビューが失敗した場合:
   - レビューレポートの推奨事項に従って `.drawio` ファイルを編集
   - PNGに再変換
   - レビューサブエージェントを再度起動（iteration + 1）
   - すべての項目が合格するまで繰り返す（最大3回）

8. **ユーザーへの提示** - すべてのチェックに合格した後のみ:
   - PNGを表示
   - 図の構造を説明
   - フィードバックを求める

## 一般的なパターン

### シンプルな線形フロー
```
Actor A: Start → Task 1 → Task 2 → End
```

### 部門横断的な引き継ぎ
```
Actor A: Task 1 → [handoff]
Actor B:         → Task 2 → Task 3
```

### 決定ゲートウェイ
```
Actor A: Task 1 → <Decision?>
             ├─ Yes → Task 2a
             └─ No  → Task 2b
```

## よくある間違い（これらを繰り返さないでください）

### ❌ 白地に白文字
**問題**: `fillColor=#ffffff` を `fontColor=#000000` なしで設定すると、テキストが見えなくなります。
**解決策**: 白い背景を持つすべての要素に必ず `fontColor=#000000;` を追加してください。

### ❌ 浮いている矢印（接続されていない）
**問題**: `<mxPoint x="100" y="200"/>` のような座標ベースの矢印を使用すると、浮いている矢印が作成されます。
**解決策**: `source="elementId" target="elementId"` を使用して矢印をボックスに接続してください。

### ❌ スイムレーンの外にある要素
**問題**: `parent="laneX"` を忘れると、要素がスイムレーンの外に配置されます。
**解決策**: スイムレーン内のすべての要素には `parent="laneX"` 属性が必須です。

### ❌ 間違ったファイル拡張子
**問題**: PNGファイルが `diagram.png` ではなく `diagram.drawio.png` という名前になっています。
**解決策**: 変換スクリプトは `${INPUT%.drawio}.png` で正しく処理するようになりました。

### ❌ セルフレビューのスキップ
**問題**: PNG出力を確認せずにユーザーに図を提示しています。
**解決策**: ユーザーレビューの前に、必ずPNGに変換し、読み込んで、チェックリストを適用してください。
