# AI臭チェックリスト

Phase 4 のレビューsubagentに渡す。draft.md を以下の観点でチェックし、指摘を出力する。

---

## 1. 表現パターン

### 禁止表現（見つけたら即指摘）

#### A. AI定番の冗長表現
- 「〜と言えるでしょう」「〜ではないでしょうか」
- 「〜することができます」（→「〜できます」）
- 「〜において」「〜における」の多用
- 「様々な」「多様な」（具体的に何か書く）
- 「〜の観点から」「〜の側面から」の連発

#### B. ドラマチック形容詞（盛り表現）
AIが文章を「すごそう」に見せるために使う。著者は口語的で温度が低い（「便利だなー」「詰まりました...」）。以下は原則禁止:
- 「劇的に」「飛躍的に」「驚異的な」
- 「爆速」「圧倒的」「革命的」
- 「痛感」「衝撃を受けた」
- 「まさに」「極めて」「非常に」の連発（1記事で2回以上は過剰）
- 「古典的かつ本質的な」のような重ね修飾
- 比喩的な動詞: 「溶かす」「織り交ぜる」「紡ぐ」「醸し出す」「育む」「寄り添う」「彩る」— 普通の動詞で書く（「溶かす」→「入れる」、「織り交ぜる」→「混ぜる」「両方書く」）

→ 代わりに: 「かなり便利だった」「思った以上に大変だった」「地味にハマった」程度の温度感で

#### C. 修辞疑問文（レトリカル・クエスチョン）
AIが読者を「物語に引き込もう」として使う手法。著者は事実を述べて次に進む。
- 「〜ではないでしょうか」（問いかけで読者を誘導）
- 「〜ではありませんか」
- 「いかがでしょうか」
- 「どうなっているでしょう」

→ 疑問形は、著者が本当に読者に問いたい場面だけに限定

#### D. 余韻演出の締め
AIが「読後感」を作ろうとして書くポエム調の締め。著者は「では〜！」で終わる。
- 「さて、次の〇〇では何を△△しようか。□□が、以前より少しだけ楽しみになっています。」パターン
- 「〜なのかもしれません。」で終わる哲学的な含み
- 「そんな〇〇が、AI時代における最も贅沢な△△なのかもしれません」
- 情景描写で余韻を残す終わり方全般

→ 著者の締めは実用的。「では〜！」「参考になれば！」「コメントいただけると嬉しいです🙏」

#### E. スローガン太字
AIはキャッチフレーズを太字にする。著者は固有名詞・技術用語を太字にする。
- **「書けば書くほど、あなたを理解するAIコーチ」** ← NG（スローガン）
- **n8n** ← OK（固有名詞）
- **Supabase (PostgreSQL)** ← OK（技術スタック名）

→ 太字にしていいもの: 固有名詞、技術用語、ツール名。文やフレーズ全体を太字にしない

### 要注意表現（文脈次第で許容）
- 「〜かもしれません」「〜と思われます」— 著者の意図的な柔らかさならOK
- 「重要」「大切」— 1記事1-2回ならOK
- 学術的権威の引用（「〇〇が提唱した△△」）— 記事内容に直結する場合はOK。箔付けのためだけに学者名を出すのはNG
- 括弧による過剰説明（「コンテキスト（背景）」「PR（プルリクエスト）」）— 読者が非エンジニアの場合はOK。テックブログでは不要

## 2. 構造パターン

### 情景描写リード（最もAI臭が強い構造）
- 冒頭が情景描写・物語調で始まっている → 即指摘
  - NG例: 「テニスを終えた後の帰り道、スマホのメモ帳に〜」
  - OK例: 「こんにちは、ひぐです。この記事では〇〇について共有します。」
- 著者のリードは「自己紹介→本題直行」。読者を物語に引き込む演出はしない

### 箇条書き過剰
- 3段以上のネスト箇条書きがある → 地の文に書き直し提案
- 本文の50%以上が箇条書き → 地の文とのバランス指摘

### 太字過剰
- 1セクションに3箇所以上の太字 → 本当に強調すべき箇所に絞る提案
- 太字が文全体やフレーズにかかっている → 固有名詞・技術用語だけに絞る（1.Eのスローガン太字ルール参照）

### パラグラフ構造
- 1文だけのパラグラフが連続 → 結合提案
- 1パラグラフが5文以上 → 分割提案

### 装飾的な区切り
- セクション間に `---`（水平線）を入れて「章立て」感を演出している → `##` だけでフラットに進める
- 見出しにコロンやダッシュで副題を付けている（例: 「PM視点：AIプロダクトで〜」）→ 著者の見出しはシンプル（例: 「難しかったところ」「まとめ」）

### 記号・括弧の多用
AIは構造を「見た目で」わかりやすくしようとして記号を多用する。著者の文はプレーンで記号に頼らない。
- `()` 括弧による補足説明が1段落に2回以上 → 本文に組み込むか、削る
- `「」` 鉤括弧の多用（強調目的で使いすぎ）→ 固有名詞・引用以外では控える
- `——`（emダッシュ）による挿入句 → 著者は使わない。読点か文分割で対応
- `……`（三点リーダー連続）でドラマチックな間を演出 → 著者が使うのは `...` 程度で控えめ
- `：`（コロン）で文中に定義を埋め込む → 著者は使わない。別文にするか箇条書きにする

→ 目安: 1段落に記号系の装飾は1つまで。記号がなくても意味が通る文が正解

## 3. 内容パターン

### 捏造チェック
- material.md にない情報が含まれていないか
- 数字・固有名詞が素材と一致するか

### 一貫性チェック
- 同じ概念に複数の表現を使っていないか（例: 「テニス記録」と「練習ログ」が混在）
- 文体が途中で変わっていないか（敬体/常体の混在）

### 人間らしさチェック
- 著者の一人称（「僕」「自分」）が使われているか
- 具体的なエピソード・体験が含まれているか
- 読者への語りかけ調が維持されているか
