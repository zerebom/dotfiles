# 競合調査 統合レポートテンプレート

このテンプレートは **メインAgentが `sources/*.md` を読み込んで統合する** ための最終成果物用。
詳細・原文引用・画像URLは `sources/{service}.md` 側に残し、こちらは比較・横断的示唆・PRDへの反映論点に専念する。

出力先: `{base_dir}/YYYY-MM-DD-{topic}/report.md`
（`{base_dir}` は `projects/{project}/research` または `references/competitors`）

```markdown
---
title: {topic} 競合調査
type: research
created: YYYY-MM-DD
status: draft
tags: [competitor-research, {project}]
---

# {topic} 競合調査

## 調査サマリー

- **調査目的**: （フェーズ1のQ1-Q2で確定した目的を1段落で）
- **参照先PRD/プロジェクト**: `projects/{project}/prds/xxx.md` の「検証」セクション等
- **調査日**: YYYY-MM-DD
- **対象サービス**: A, B, C

## TL;DR（3行サマリー）

各サービスを1行ずつ、「どう違うか」の軸で要約。

- **A**: …
- **B**: …
- **C**: …

## サービス別詳細

各サービスの詳細（UI/UXステップ、原文引用、スクショ、API仕様、参照URL）は `sources/` 配下を参照。このレポートでは重複記載しない。

- **サービスA**: [sources/{service-a}.md](./sources/{service-a}.md) — 2〜3行の抜粋サマリー（「〇〇方式を採用。認可UIは3ステップ」程度）

- 明確に割れている論点: …
- 意外な発見: …

## PRDへの示唆

フェーズ1のQ1・Q4で聞いた「特に詰めたい論点」に対して、調査結果からの示唆を箇条書きで：

- 論点X → Aは〇〇方式、B/Cは△△方式。Voiceとしては…（提案）
- 論点Y → 3社とも共通仕様。採用が妥当
- 論点Z → 各社バラつきあり。要判断

## 未解決・追加調査候補

- 〇〇の挙動は公式情報では確認できなかった。実アカウントでの検証が必要
- サービスDも後で追加調査する価値あり（類似機能を持つため）
```

## 記入時の注意

- **比較表の観点**はフェーズ1のQ2・Q4で合意した内容に差し替える。汎用観点を埋めるだけにしない
- **画像**は必ず公式ヘルプページ等の一次ソース由来のURLを埋め込む。見つからない場合は該当ページアンカーURLで代替
- **推測と事実を分離**する。「所感（推測）」セクションに隔離し、「推測:」プレフィックスを付ける
- **参照ソース**はサービスごとにセクション末尾にまとめる。本文中でも `[...](URL)` 形式でリンクする
- **フロントマター**の `tags` には `competitor-research` を必ず含める（後から検索可能にするため）
