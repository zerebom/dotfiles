# Webページ（LP・サイト）の設計ガイド

SKILL.mdの「成果物タイプ別の検討」をより詳細に解説する。

## よくある失敗パターン

### 1. 機能を並べただけ

```
悪い例:
「CEP分析機能」「AIチャット機能」「レポート機能」

なぜダメか:
- 機能は「何ができるか」であり、「なぜ嬉しいか」ではない
- 対象が「で、私に何のメリットがあるの？」と思う
```

```
改善例:
「顧客が『買いたい』と思う瞬間を特定し、施策の精度を上げる」

なぜ良いか:
- 対象にとっての価値（施策の精度が上がる）が明確
- 機能ではなく、結果を伝えている
```

### 2. 専門用語で煙に巻く

```
悪い例:
「CEP（カテゴリーエントリーポイント）分析で市場を再定義」

なぜダメか:
- CEPを知らない人には意味不明
- 「市場を再定義」も抽象的で何も伝わらない
```

```
改善例:
「顧客がなぜ・いつ買おうと思うのか、その瞬間を可視化する」

なぜ良いか:
- 専門用語なしで、やることが伝わる
- 具体的なイメージが湧く
```

### 3. 主語がない・曖昧

```
悪い例:
「価格で選ぶ」「時短したい」「品質重視」（図の中の言葉）

なぜダメか:
- 誰が？何の話？文脈がない
- ツールがこれを出力するのか、分析軸なのか、不明
```

```
改善例:
「顧客の購買理由を自動分類: 価格重視 / 品質重視 / 時短ニーズ...」

なぜ良いか:
- 「ツールが自動分類する」という主語が明確
- 何の情報かが分かる
```

### 4. 行動喚起の矛盾

```
悪い例:
- 「無料で始める」（セルフサーブ型）
- 「デモを予約」（セールス対応型）
が同時に存在

なぜダメか:
- どちらに進めばいいか迷う
- 高機能ツールなのに「無料で始める」は信頼性を損なう可能性
```

```
改善例:
サービスの導入形態に合わせて一本化する
- セルフサーブ型なら「無料で始める」をメインに
- セールス対応型なら「デモを予約」をメインに
```

## 内容設計のフレームワーク

### 見出し（ヘッドライン）の作り方

```
構造: [対象の課題] → [解決] → [結果の価値]

例:
課題: 顧客の声が大量にあるが、活用できていない
解決: AIが自動で分析・分類
結果: マーケ施策の精度が上がる

見出し案:
「顧客の声を、成果につながる施策へ。」
「VoC分析の時間を10分の1に。本当の仕事に集中しよう。」
```

### 避けるべき見出しパターン

| パターン | 例 | 問題 |
|---------|-----|------|
| 機能そのまま | 「VoC分析ツール」 | 価値が伝わらない |
| 抽象的すぎ | 「ビジネスを加速する」 | 何のことか分からない |
| 誇大表現 | 「革命的」「唯一無二」 | 信頼性を損なう |
| 業界用語 | 「CEP分析でCXを最適化」 | 伝わらない |

### 信頼を得るための要素

対象が「本当に？」と思ったときに答えられる根拠を用意する。

```
種類と優先順位:

1. 具体的な数字（最も強い）
   - 「導入企業の平均で、分析時間を月120時間削減」
   - ただし、出典・条件を明記すること

2. 顧客事例・声（強い）
   - 「〇〇社のマーケ担当者: こういう成果が出た」
   - 実名・実社名があるとより強い

3. 第三者評価（強い）
   - 受賞歴、メディア掲載、認証

4. 実績数（中程度）
   - 「導入企業300社」
   - 数字だけだと「で、効果は？」となる

5. 機能の詳細説明（弱い）
   - 信頼というより理解を助けるもの
```

## 構成設計のフレームワーク

### 基本構造

```
1. 掴み（ヒーロー）
   - 対象の課題に共感を示す or 解決後の理想を見せる
   - 「自分に関係ある」と思わせる

2. 課題の深掘り（オプション）
   - 対象が抱える課題を言語化
   - 「そうそう、それが困ってた」と思わせる

3. 解決策の提示
   - どうやって課題を解決するか
   - 機能ではなく、価値として伝える

4. 具体的な内容（機能・特徴）
   - 何ができるか、どう使うか
   - スクリーンショットや図解が有効

5. 信頼の証拠
   - 実績、事例、数字
   - 「本当に効果あるんだ」と思わせる

6. 行動喚起（CTA）
   - 具体的に何をしてほしいか
   - ハードルを下げる（無料、簡単、すぐ等）
```

### 構成の検証

- 各セクションは前のセクションを受けて自然につながっているか
- 「なぜ？」と思う箇所に、次のセクションで答えているか
- 最も重要なメッセージは十分に目立つ位置にあるか

- [ ] 専門用語を使う場合、対象は理解できるか
- [ ] 「効率化」「最適化」などの曖昧語を具体化したか
- [ ] 主語は明確か（誰が何をするのか）
- [ ] 機能ではなく価値を伝えているか
- [ ] 誇大表現になっていないか
- [ ] 数字に出典・条件はあるか
