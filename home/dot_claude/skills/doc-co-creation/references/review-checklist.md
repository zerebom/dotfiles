# レビューチェックリスト

ドキュメントのレビュー時に使用するチェックリスト。
複数の視点から抜け漏れや問題点を指摘し、改善提案を行う。

---

## 1. 読者視点チェック

読者の立場になって、理解しやすさを確認する。

### チェック項目

- [ ] **読者の特定**: 誰が読むドキュメントか明確か？
- [ ] **目的の明示**: このドキュメントを読んで何ができるようになるか分かるか？
- [ ] **前提知識**: 読者の知識レベルに合っているか？専門用語は適切に説明されているか？
- [ ] **結論の位置**: 忙しい読者が冒頭だけ読んでも要点が分かるか？
- [ ] **自己完結性**: このドキュメントだけで理解できるか？外部参照が多すぎないか？

### 指摘例

- 「冒頭に『CEP』という略語が説明なく使われています。初出時に定義を追加してください。」
- 「このドキュメントは経営層向けですか？現場向けですか？読者によって必要な詳細度が変わります。」
- 「『後から背景情報なしで読み返しても理解できる』と書いてありますが、用語の定義がないため達成できていません。」

---

## 2. 構成・構造チェック

論理的な流れと構造を確認する。

### チェック項目

- [ ] **論理の流れ**: 各セクションが論理的につながっているか？
- [ ] **粒度の一貫性**: 同じレベルの見出しが同じ粒度になっているか？
- [ ] **重複の排除**: 同じ内容が複数箇所に書かれていないか？
- [ ] **過剰な構造化**: フレームワークを無理に当てはめていないか？
- [ ] **抜け漏れ**: 必要な情報が欠けていないか？

### 指摘例

- 「GROW フレームワークを使っていますが、内容が各セクションに散らばっており、かえって読みにくくなっています。」
- 「『1.1 ビジネス』『1.2 提供価値・運用』『1.3 プロダクト』『1.4 組織・リソース』と4つに分かれていますが、内容に重複があります。」
- 「Goal セクションと KR セクションで同じ内容が異なる表現で書かれています。一箇所にまとめてください。」

---

## 3. 表現・文体チェック

読みやすさと適切な表現を確認する。

### チェック項目

- [ ] **AI的表現の排除**: 過度な太字、箇条書きの乱用がないか？
- [ ] **曖昧表現の排除**: 「〜と思われる」「〜かもしれない」が多用されていないか？
- [ ] **修飾語の適切さ**: 「非常に」「とても」「極めて」が乱用されていないか？
- [ ] **造語・略語の説明**: 初出時に定義されているか？
- [ ] **事実と願望の区別**: 「〜である」と「〜を目指す」が混同されていないか？

### 避けるべき表現パターン

**太字の過剰使用**:
```
❌ **CS による手動の VoC 分析レポート** / **CS の工数に強く依存してスケールしづらい**
✅ CS による手動の VoC 分析レポートが主な価値だが、CS 工数に依存しスケールしにくい
```

**箇条書きの乱用**:
```
❌ - **CEP定量化ダッシュボード**
   - **AIチャット（分析アシスタント）**
   - **X など外部データとの統合ビュー**
   については「これから作る」フェーズ。

✅ CEP定量化ダッシュボード、AIチャット、外部データ統合ビューは今後開発予定。
```

**未来の断定**:
```
❌ CS は「投稿を全部読む人」から「インサイトを解釈するファシリ」へシフトしている。
✅ CS は「投稿を全部読む人」から「インサイトを解釈するファシリ」へシフトすることを目指す。
```

**曖昧な修飾語**:
```
❌ 「地味だけど効く」CS向け機能
❌ 「尖ったプロダクト＋高付加価値 CS」
✅ 集計・フィルタリング時間を30%削減するCS向け機能
✅ 特定用途に特化したプロダクトと、戦略立案まで支援するCS
```

### 指摘例

- 「このセクションで太字が8箇所使われています。本当に強調したい1-2箇所に絞ってください。」
- 「『〜になっている』と断定していますが、これは現状ですか？目標ですか？」
- 「『体感30％ほど減っている』は根拠が不明です。測定方法と数値を明記してください。」

---

## 4. 具体性・根拠チェック

主張に根拠があるかを確認する。

### チェック項目

- [ ] **数字の根拠**: 記載された数字に根拠があるか？
- [ ] **具体例の有無**: 抽象的な説明に具体例が添えられているか？
- [ ] **前提の明示**: 数字や計画の前提条件が明記されているか？
- [ ] **測定可能性**: KPIや目標は実際に測定できるか？

### 指摘例

- 「『40h → 25h 以下に削減』とありますが、現状の40hはどのように測定していますか？25hの根拠は？」
- 「『7社以上』という目標の根拠を教えてください。現状何社で、なぜ7社が適切なのですか？」
- 「『スケールしづらい』と書いてありますが、具体的にどの程度の規模で限界が来るのですか？」

---

## 5. 全体整合性チェック

ドキュメント全体の一貫性を確認する。

### チェック項目

- [ ] **用語の統一**: 同じ概念に複数の呼び方をしていないか？
- [ ] **数字の整合**: 複数箇所に出てくる数字が一致しているか？
- [ ] **目的との整合**: 冒頭で述べた目的を達成する内容になっているか？
- [ ] **TODO・TBD の残存**: 未完成の部分が残っていないか？

### 指摘例

- 「『CEP』と『カテゴリーエントリーポイント』が混在しています。どちらかに統一してください。」
- 「冒頭で『一枚で参照できる』と書いてありますが、実際は10ページ以上あります。目的を見直すか、内容を圧縮してください。」
