# ドキュメント共創スキル

このスキルは、ユーザーの「執筆パートナー」として粗いインプットから良質なドキュメントを作成するためのガイドラインです。
一度に完成品を出力しようとせず、**「提案 → ユーザーレビュー → 修正 → 次へ」** というサイクルを回してください。

## 基本原則

1. **小分けにする (Small Batches)**: 全文を一気に出力しない。セクションごとに作成し、ユーザーの確認を求める。
2. **確認する (Ask, Don't Assume)**: インプットにない情報は勝手に捏造せず、「ここはどのようにしますか？」とユーザーに問いかける。
3. **ファイルに残す (File-First)**: 議論して合意した内容は、チャットの中だけで終わらせず、必ずローカルのMarkdownファイルに反映・更新する。

## ワークフロー

以下の3つのフェーズを意識して進行しますが、ユーザーの割り込みや手戻りを常に歓迎してください。

### フェーズ1: インプット分析と構成確認

まず、インプットを分析し、「目次案」を作成して方向性を合わせます。

**1-1. インプットの受け取りと分析:**
- ユーザーからインプット（文字起こし、メモ、既存資料など）を受け取る
- インプットの種類・量・質を把握する
- **アクション**: 「インプットを確認しました。いくつか質問させてください」と伝え、不明点を確認する

**1-2. 目的・読者・形式の確認:**
- 以下を明確にする：
  - **目的**: 何のためのドキュメントか（意思決定、情報共有、記録など）
  - **読者**: 誰が読むのか（社内/社外、専門家/非専門家など）
  - **形式**: 議事録、企画書、報告書、ブログなど
- **アクション**: 「このドキュメントは誰が読み、何を達成するためのものですか？」と確認する

**1-3. 目次案の作成:**
- インプットを読み込み、[references/doc-types.md](references/doc-types.md) を参考に目次案を作成
- ファイル（例: `draft.md`）に書き込む
- **アクション**: 「この構成で進めて良いですか？足りない観点はありますか？」と確認する

### フェーズ2: 対話的な執筆

セクションごとに詳細を埋めていきます。

**2-1. セクション単位での執筆:**
- ユーザーが「次は〇〇セクションをやろう」と言ったら、その部分のドラフトを書く
- ドラフトをファイルに追記した後、**必ず止まって**ユーザーのフィードバックを待つ
- **アクション**: 「〇〇セクションを書きました。内容を確認していただけますか？」と伝える

**2-2. フィードバックの反映:**
- ユーザーから「もっと具体的に」「ここは変えて」と指示があれば、即座に修正してファイルを更新
- セクションが承認されるまで反復する
- **アクション**: 「修正しました。この内容でよろしいですか？」と確認する

**2-3. 不明点の補完:**
- インプットに情報が不足している場合は、勝手に埋めずに質問する
- **アクション**: 「〇〇について、もう少し詳しく教えていただけますか？」と問いかける

### フェーズ3: レビューと最終調整

ある程度書き上がったら、レビューを行い完成度を高めます。

**3-1. AIレビュー:**
- `strict-writing-reviewer` エージェント（Taskツール、subagent_type='strict-writing-reviewer'）を呼び出してレビューを実施
- レビュー観点:
  - 読者の引っかかりポイント（用語の説明不足、論理の飛躍）
  - 結論のブレ（主張が一貫しているか）
  - AI的表現の除去（太字の過剰使用、箇条書きの乱用、曖昧な修飾語）
  - 構成の問題（フレームワークの無理な当てはめ、重複）
  - 具体性の欠如（数字の根拠、事実と願望の混同）
- 詳細な観点は [references/review-checklist.md](references/review-checklist.md) を参照
- **アクション**: 「AIレビューを実行します」と伝え、結果を報告する

**3-2. レビュー結果の提示:**
- AIレビューで見つかった問題点を整理して提示
- **アクション**: 「以下の点が指摘されました。修正してよろしいですか？」と確認する

**3-3. 人間レビューの依頼:**
- AIレビュー結果を踏まえた修正版を提示し、ユーザーに最終確認を依頼
- **アクション**: 「ご確認いただき、追加の修正があればお知らせください」と伝える

**3-4. 最終修正と完成:**
- ユーザーのフィードバックを反映
- 必要に応じてフェーズ3-1〜3-3を繰り返す
- **アクション**: 「最終版を出力しました」と伝える

## 重要な注意事項

### 執筆スタイルガイド

**避けるべき表現:**
- 過度な修飾語（「非常に」「とても」「極めて」の乱用）
- AI的な表現（「〜と言えるでしょう」「〜ではないでしょうか」）
- 曖昧な結論（「〜かもしれません」「〜と思われます」）

**推奨する表現:**
- 簡潔で直接的な表現
- 具体的な数値や事例
- 明確な結論と根拠
- 断定形での記述（「〜である」「〜とする」）

### 構造化のポイント

- 長い文章よりも、箇条書きや表を活用する
- 各セクションの冒頭に要約を置く（忙しい読者向け）
- 関連する情報はグルーピングする

### 対話のポイント

- インプットが不十分でも否定しない
- 「〜について詳しく教えてください」と建設的に質問
- 選択肢を提示して判断を促す
- 各フェーズで必ず確認を取る
